# EU AI Act Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Art. 50 transparency (#336), the compliance report with audited approval decisions (#339), and the Art. 5 prohibited-practice detectors (#337) in 3.0.0.

**Architecture:**
- All three reuse the "informational audit entry" pattern from redaction: `Severity.None` plus a fixed `PolicyCode`, kept out of threat counts.
- **Transparency** lives in `SentinelPipeline`, after the response scan and restore.
- **Approval decisions** are audited by one decorator around whatever `IApprovalStore` is registered.
- **The report** is a new `sentinel report` CLI command that only reads the audit SQLite file.
- **The Art. 5 detectors** are `SemanticDetectorBase` subclasses in a new `Compliance` category, with thresholds tuned against a real embedding model.

**Tech Stack:** .NET 8/9/10, Microsoft.Extensions.AI 10.11, System.CommandLine (CLI), Microsoft.Data.Sqlite, xunit.v3. For the evaluation: ONNX Runtime with a small sentence-embedding model, or a reachable hosted provider.

**Spec:** `docs/superpowers/specs/2026-10-17-eu-ai-act-design.md`

## Global Constraints

- **No content in outputs.** Message text, redacted values, personal data, session ids and caller ids never go into audit entries, reports, logs or exceptions. Counts, codes, detector ids, policy names, tool names and request ids only.
- **Informational audit entries.** New audit entries use existing `AuditEntry` fields only, with `Severity.None` and a fixed `PolicyCode`. They never move threat tiles, trend, risk score, `SentinelMetrics.Threats` or alerts.
- **API.** Public API changes are additive, except `DetectorCategory.Compliance`. New options are settable or init properties.
- **Build hygiene.** Analyzers run as errors. The AOT and trim analyzers stay clean (`AI.Sentinel` has `IsAotCompatible`). `dotnet format whitespace . --folder --verify-no-changes` passes.
- **PRs and commits.**
  - **Three PRs, each branched from a fresh `origin/main`:** Tasks 1–5 (#336), Tasks 6–8 (#339), Tasks 9–10 (#337).
  - **Commit messages:** type `feat`, no nested parentheses in bodies, no body line starting with a conventional type followed by a colon, and each commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Tests.** Run with `dotnet test tests/AI.Sentinel.Tests -- --filter-class "*<Name>*"`. Run the full `dotnet test` before each push.

## Review Focus

1. **Notice text copied into a later user message.** A user pasting the notice text into their own message is not stripped. Only assistant-role leading `TextContent` that exactly equals `Notice` is removed. The test belongs to Task 3.
2. **The same session on two named pipelines.** Each pipeline discloses once in that session, because the tracking is per pipeline. The test belongs to Task 3.
3. **An empty or missing audit file for the report.** Exit 0 with "no entries in period" sections for an empty file. A clear error and non-zero exit for a missing file; never create it. The test belongs to Task 8.
4. **An approval decided twice from different processes.** A second dashboard approve on an already-settled request writes no second `APPROVED` entry. The admin call returns without changing state, and the decorator only audits when the request was pending before the call. The test belongs to Task 6.
5. **A Compliance detector on a reply quoting the user's prohibited request.** Both legs fire, and each fires once per leg. The report counts detections per leg as entries, as for other detectors. The test belongs to Task 9.

**Interfaces:**

    - `static AuditEntry Decision(string policyCode, string policyName, string toolName, string requestId)` builds the entry.

Rules:
- **Admin decisions.** `ApproveAsync` and `DenyAsync` through the wrapper write `APPROVED` or `DENIED`, but only when the request was pending immediately before the call, read through the inner store's state lookup.

- **Time-out.** It is written when `WaitForDecisionAsync` returns `Pending` at its deadline.
- **Stores without `IApprovalAdmin`** (Entra PIM): write `APPROVED` the first time this process observes `Active` for a request id, and `DENIED` on `Denied`.
- **Duplicates.** The report counts distinct request ids per outcome, so a duplicate from another process is harmless.
- **Summary contents.** Never the arguments, the approver note, the caller id or the approver id.
- **Errors.** Audit failures are logged and never fail the decision.

  - `internal static ValueTask<ComplianceReport> BuildAsync(IAuditStore store, DateTimeOffset from, DateTimeOffset to, string auditFilePath, TimeProvider time, CancellationToken ct)`
  - `ComplianceReport` is an immutable model with `int Schema = 1`. It holds:
    - **header:** the period, the generation time, the audit file path and the disclaimer text;
    - **`Art12`:** the chain result (intact, entries checked, first broken id), entries in the period, and counts per `Source` (null shown as `in-process`);

    - **`Art10`:** redaction counts per entity type, parsed from `REDACTED` summaries, and the count of fallback entries (summary ending `; not redacted`);

    - **`Art5`:** detections per `CMP-` detector id and severity;
    - **`Art15`:** all other detections per detector id and severity, plus the top 5 detectors.

Rules:
- Chain verification runs over the whole file, oldest first. The report notes that a trimmed head (retention) is verified from the oldest retained entry.
- The model never holds `Summary` text, except values parsed from `REDACTED` and approval summaries into counts, and never session or caller ids.
