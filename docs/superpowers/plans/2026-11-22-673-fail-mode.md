# Fail mode from the profile when no decision can be made (#673) Implementation Plan

**Goal:** Decide what happens when no policy decision can be made: no valid profile, an expired profile, or every evaluator failing. The profile's `fail_mode` decides, closed by default (ADR-237, ADR-231).

**Issue:** #673, milestone "Controlled from a central server". Depends on #658.

**Spec:** Outline document `6888019f-3202-4ea3-93a7-213cc8811bf0` ("AI.Sentinel: be controlled from Themis.NET") and its approved design, Outline document `b4b02d34-d3a1-4141-b5a0-4d51bcba7d91` ("AI.Sentinel: central server control, design", Status: approved). Read both with the Outline connector before writing code. Where they differ, the design wins; where the design and an accepted ADR differ, the ADR wins. #653 and #657 are replaced by the design and are not a source.

## Acceptance criteria

From the issue. Each has a test or check named after it.

- With `fail_mode` **closed** (the default), a call that cannot be decided is denied with guidance that says why and what the developer can do. `FailModeTests`.
- With `fail_mode` **ask**, set by the node, such a call gets **ask**, mapped per CLI as in #670. `FailModeTests`.
- With a server configured but no profile at all, including the developer not signed in yet, the hook uses **closed** and tells the developer to sign in. With no server configured there is no profile to miss, and the hooks behave as before. `FailModeTests`.
- In both modes, `read` and `search` calls on paths inside the repository stay allowed. `FailModeTests`.
- A policy bundle that errors at runtime denies and names the bundle, whatever the fail mode. `FailModeTests`.
- An internal error in the hook itself still fails closed, as today. `FailModeTests`.
- With none of the new settings, behaviour is unchanged. Existing suite.
